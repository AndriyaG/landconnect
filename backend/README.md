# LandConnect API
1. Setup: `cd backend && python -m venv .venv && .venv\Scripts\activate && pip install -r requirements.txt`, then copy `.env.example` to `.env` and fill in values.
2. Run locally: `uvicorn app.main:app --reload --host 0.0.0.0 --port 8000` (tables are created on startup; check `GET /health`).
3. Test: `pytest` (uses `TEST_DATABASE_URL` if set, otherwise a temporary SQLite DB; Stream is stubbed). The test DB is wiped on every test, so never point it at real data.
4. Seed demo data: `python -m app.seed` (uses `DATABASE_URL` from `.env`; safe to rerun). Creates 8 listings around Bengaluru with picsum.photos images. Demo logins, all with password `landconnect123`: `demo.buyer@example.com` (buyer), `demo.seller@example.com` (seller), `demo.broker@example.com` (broker).
5. Listing images: `POST /listings/{id}/images` accepts JPEG/PNG/WebP up to 5 MB. Images are resized to a max of 1600px, re-encoded as JPEG, stored in the `stored_images` table and served from `GET /images/{id}`. Image URLs in responses are either relative (`/images/{id}`, prefix with the API URL) or external `https://` URLs.
6. Chat, calls, and meetings: conversations are created with `POST /conversations`. Messages travel over `GET /ws` (`auth`, then `send` with `client_id`) and are stored for `GET /conversations/{id}/messages`. `POST /blocks` stops both users from messaging, calling, or being invited to a meeting (403 `blocked` either way). Phone numbers in a message are stored with all but the last two digits replaced. `POST /calls/start` creates a Stream call server-side (with ring) and a call log; it returns 403 `blocked` if either user blocked the other, and 403 `not accepting calls` when the callee's `call_privacy` is `contacts` and there is no conversation. `POST /calls/{call_id}/status` is participants only. `GET /calls/history` lists the current user's calls. `POST /meetings` creates a meeting for the host and the invited user ids; `GET /meetings` lists meetings you belong to; `POST /meetings/{id}/join` returns the `call_id` for participants only and opens the Stream call with `ring: false`.
7. Stream dashboard (do this once; the app does not set it): Video & Audio → Call Types → `default` → Permissions. Remove `CreateCall`, `UpdateCall`, and `UpdateCallMember` from the `user` role so the mobile SDK cannot create or ring calls. Keep `JoinCall`, `ReadCall`, `SendAudio`, `SendVideo`, and `EndCall` on `call_member`. The backend uses the API secret, which bypasses those grants.
8. Deploy: push to GitHub, then in Render choose New > Blueprint and select this repo (`render.yaml`, root directory `backend`).
9. In Render set `DATABASE_URL`, `JWT_SECRET`, `STREAM_API_KEY`, `STREAM_API_SECRET`, and put the service URL in `mobile/eas.json` as `EXPO_PUBLIC_API_URL`.
